Modifiers

Modifiers are runtime contributions applied to an attribute calculation. In v1.4 you can still use the legacy AddModifier workflow, but the recommended workflow is now Add Typed Modifier plus a Formula Profile. This lets you decide exactly how each bucket of modifiers affects the final Max value.

The important change in v1.4

A typed modifier does not say "add this and multiply that" directly. It writes one Magnitude into a named Modifier Bucket. The active Formula Profile reads those buckets and calculates the attribute Max value.

Why Modifiers Exist

Modifiers solve a classic stacking problem. If you directly subtract and then re-add values, overlapping buffs and debuffs can easily restore the wrong amount and leave the attribute in an invalid state.

Example 
Movement Speed Base Value = 500

Enemy debuff: Flat = -300
New Max = 500 - 300 = 200

Snow debuff: Flat = -400
New Max = 500 - 700 = -200 -> clamped by your attribute rules

Enemy debuff ends
New Max = 500 - 400 = 100

Snow debuff ends
New Max = 500

The key benefit is that removing one modifier never restores the wrong value. Stats_X recalculates the final result from the full active stack every time, using dirty flags so the work happens only when needed.

Legacy Formula vs Typed Formula

By default, Stats_X keeps the legacy formula for compatibility:

Legacy 
Max = (Base + Sum(LegacyAdditive)) * Product(LegacyMultiplicative)

The new typed workflow uses named buckets. The built-in PoELike profile uses this formula:

Built-In PoELike 
Max = (Base + Flat + LegacyAdditive) * (1 + Increased / 100) * More * LegacyMultiplicative
Typed modifiers need a matching formula

If an attribute uses the default Legacy profile, typed buckets such as StatsX.ModifierBucket.Flat, StatsX.ModifierBucket.Increased, and StatsX.ModifierBucket.More are stored but do not affect the final value. Use PoELike or a custom DataAsset formula that reads those buckets.

Built-In Modifier Buckets

A bucket decides how multiple modifiers are grouped before the formula runs. The built-in typed buckets are:

Bucket Tag Aggregation Magnitude Meaning
StatsX.ModifierBucket.Flat Sum Flat value added to Base. Example: 50 means +50 Max.
StatsX.ModifierBucket.Increased Sum Percentage points. Example: 20 means +20% in the PoELike profile.
StatsX.ModifierBucket.More Product Multiplier. Example: 1.3 means 30% more, 0.7 means 30% less.
PoELike Example 
Movement Speed Base = 500
Flat bucket = +50
Increased bucket = +20
More bucket = 1.3

Max = (500 + 50) * (1 + 20 / 100) * 1.3
Max = 858

Choose a Formula Profile

A Formula Profile tells Stats_X how to turn Base, buckets, and dependencies into the final attribute Max. The profile is resolved in this order:

  1. Per-attribute override on the stats component.
  2. Default Formula Profile on the stats component.
  3. Project Settings, Plugins > Stats_X Runtime > Formula Profiles.
  4. Legacy fallback.
Use Legacy for old projects

Legacy keeps existing AddModifier behavior. It is the safest option for projects that already shipped graphs using additive and multiplicative values.

Use PoELike for the new built-in typed workflow

Choose Source = Built-In Formula and Built-In Formula = PoELike when you want Flat, Increased, and More buckets to affect the attribute.

Use Data Asset for custom math

Choose Source = Data Asset when you want a designer-authored formula with custom buckets, custom aggregation, or dependencies on other attributes.

Set the formula before adding typed modifiers

Formula profiles bind bucket definitions to the attribute runtime cache. In practice, configure the project, component, or attribute Formula Profile before your gameplay starts adding typed modifiers.

Add a Typed Modifier in Status Forge

In Status Forge, use the Add Typed Modifier node when a status should add one contribution to a formula bucket.

Target the correct stats component

Set Stats Component Target to the component that owns the attribute. For most effects, this is the target actor stats component. For self-buffs, it can be the caster component.

Choose the affected attribute

Set Attribute Tag to the attribute whose Max should be recalculated, such as StatsX.Attribute.Stat.MovementSpeed or StatsX.Attribute.Resource.Health.

Choose the source and bucket

Set Source Tag to a gameplay category used for filtering, then set Modifier Bucket Tag to the formula bucket that should receive the magnitude.

Set Magnitude and Priority

Magnitude is interpreted by the selected bucket. Priority only matters for custom buckets using Override By Priority; the built-in Flat, Increased, and More buckets ignore it.

Add Typed Modifier Pin Example Meaning
Stats Component Target Target stats component The component that owns the modified attribute.
Attribute Tag StatsX.Attribute.Stat.MovementSpeed The attribute whose Max value will be recalculated.
Source Tag StatsX.ModSource.Boots A category used later for queries or filtered removal.
Modifier Bucket Tag StatsX.ModifierBucket.Increased The bucket that receives the magnitude.
Magnitude 20 For Increased, this means +20 percentage points.
Priority 0 Used by Override By Priority buckets. Otherwise leave it at 0.
Modifier Instance ID Output value Save it if you need to remove this exact modifier instance later.
Server-side only

Add and remove modifiers only on the server. Modifier state and recalculated attributes replicate to clients through the Stats_X runtime.

Remove Typed Modifiers

Use the existing Remove Modifier node to remove both legacy and typed modifiers. The removal node uses filters, and all active filters must match.

  • Remove by Modifier Instance ID removes one exact modifier returned by Add Typed Modifier.
  • Remove by Source Owner ID removes modifiers owned by one status, item, or external system.
  • Remove by Source Tag removes one source category, such as boots, aura, poison, or slow.
  • Remove by Attribute Tag removes modifiers affecting one attribute.
  • Count to Remove = 0 means remove every modifier matching the active filters.
Status Forge cleanup pattern

Add Typed Modifier uses the current Status ID as the modifier owner. If the status should clean up its modifiers when it ends, make sure its OnEnd path runs for that termination type, then use This ID as Remove by Source Owner ID to remove the modifiers created by that status instance.

Create a Custom Formula with a DataAsset

A Formula DataAsset is the best option when your attribute math is more specific than the built-in Legacy or PoELike profiles. It is a stack-based formula: each step pushes values onto a small stack or combines values already on the stack.

Create the formula asset

In the Content Browser, create a Data Asset and choose PDA_StatsXFormulaProfile. Name it clearly, for example DA_Formula_AttackPower.

Declare the buckets the formula can read

Add entries to Bucket Definitions. Each entry has a bucket tag, an aggregation mode, and a default value used when no active modifier exists for that bucket.

Declare dependency attributes

Add every external attribute that the formula reads to Dependency Attributes. A formula can read a dependency's recalculated Max value with Load Dependency Attribute.

Write the expression steps

Add operations to Expression Steps in stack order. The last step must be Return.

Assign the formula to an attribute

On the stats component, add a per-attribute override, set Source = Data Asset, and assign the formula asset. You can also set it as the component default or project default if many attributes share the same math.

Formula DataAsset Rules

  • Every Load Bucket step must reference a bucket declared in Bucket Definitions.
  • Every Load Dependency Attribute step must reference an attribute declared in Dependency Attributes.
  • Bucket tags and dependency tags must be valid and cannot be duplicated.
  • The formula must contain at least one expression step.
  • The final step must be Return, and Return must not appear before the end.
  • The formula stack cannot exceed 16 values.
  • If a dependency is missing on the component, or the formula depends on the same attribute it is calculating, Stats_X falls back to Legacy and logs a warning.

Expression Operations

Operation What It Does
Load Base Pushes the target attribute Base value.
Load Bucket Pushes one declared bucket value, or its default value if empty.
Has Bucket Value Pushes 1 if the bucket has at least one active modifier, otherwise 0.
Load Dependency Attribute Pushes the recalculated Max value of one declared dependency attribute.
Constant Pushes a fixed number.
Add, Subtract, Multiply, Divide Safe Combines the top two stack values and pushes the result.
Min, Max Combines the top two stack values and keeps the smaller or larger result.
Clamp Consumes Value, Min, and Max from the stack and pushes the clamped value.
Select Consumes Condition, True Value, and False Value, then pushes one selected value.
Return Returns the top stack value as the new attribute Max.

Medium Custom Formula Example

This example calculates AttackPower from its own Base value, three modifier buckets, and two dependency attributes: Strength and Dexterity.

Design Goal 
AttackPower Max = Clamp(
    (Base + Flat + StrengthMax * 0.5 + DexterityMax * 0.25) * (1 + Increased / 100) * More,
    0,
    Cap
)

First, create these Gameplay Tags if they do not already exist:

  • StatsX.Attribute.Stat.AttackPower
  • StatsX.Attribute.Stat.Strength
  • StatsX.Attribute.Stat.Dexterity
  • StatsX.ModifierBucket.Cap

Then set the formula asset like this:

Bucket Aggregation Default Purpose
StatsX.ModifierBucket.Flat Sum 0 Flat attack power bonuses.
StatsX.ModifierBucket.Increased Sum 0 Percentage attack power increases.
StatsX.ModifierBucket.More Product 1 Multiplicative more or less effects.
StatsX.ModifierBucket.Cap Min 999999 Optional cap. Multiple cap modifiers keep the lowest cap.

Add these dependency attributes to the asset:

  • StatsX.Attribute.Stat.Strength
  • StatsX.Attribute.Stat.Dexterity

Finally, enter this expression step list. This is Reverse Polish Notation: values are loaded first, then combined by later operations.

# Operation Argument Stack Meaning
1 Load Base - Start from AttackPower Base.
2 Load Bucket Flat Push flat bonuses.
3 Add - Base + Flat
4 Load Dependency Attribute Strength Push Strength Max.
5 Constant 0.5 Strength scaling factor.
6 Multiply - StrengthMax * 0.5
7 Add - Add scaled Strength.
8 Load Dependency Attribute Dexterity Push Dexterity Max.
9 Constant 0.25 Dexterity scaling factor.
10 Multiply - DexterityMax * 0.25
11 Add - Add scaled Dexterity.
12 Load Bucket Increased Push increased percentage points.
13 Constant 100 Convert percentage points.
14 Divide Safe - Increased / 100
15 Constant 1 Base multiplier.
16 Add - 1 + Increased / 100
17 Multiply - Apply increased multiplier.
18 Load Bucket More Push product of more multipliers.
19 Multiply - Apply more multiplier.
20 Constant 0 Clamp minimum.
21 Load Bucket Cap Clamp maximum.
22 Clamp - Clamp final AttackPower between 0 and Cap.
23 Return - Return the final Max value.
Numerical Example 
AttackPower Base = 100
Flat bucket = 25
Strength Max = 40
Dexterity Max = 20
Increased bucket = 30
More bucket = 1.2
Cap bucket = 220

Before clamp = (100 + 25 + 40 * 0.5 + 20 * 0.25) * (1 + 30 / 100) * 1.2
Before clamp = 234

Final Max = Clamp(234, 0, 220) = 220

To feed this formula from gameplay, every effect still uses Add Typed Modifier. Only the bucket and magnitude change.

  • A sword bonus uses Modifier Bucket Tag = StatsX.ModifierBucket.Flat and Magnitude = 25.
  • A power buff uses Modifier Bucket Tag = StatsX.ModifierBucket.Increased and Magnitude = 30.
  • A temporary aura uses Modifier Bucket Tag = StatsX.ModifierBucket.More and Magnitude = 1.2.
  • A curse cap uses Modifier Bucket Tag = StatsX.ModifierBucket.Cap and Magnitude = 220.
Dependency propagation

If Strength or Dexterity changes, Stats_X marks dependent attributes dirty too. That means AttackPower is recalculated from the updated dependency values without manually rebuilding the formula.
